This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Root (all apps via Turborepo)
```sh
pnpm dev          # run all apps in dev mode
pnpm build        # build all apps
pnpm lint         # lint all apps
pnpm format       # format all files with Prettier
pnpm check-types  # typecheck all apps
```

### Server (`apps/server/`)
```sh
pnpm dev                  # run with tsx watch + dotenv
pnpm test                 # run all tests (unit + e2e)
pnpm test:unit            # run unit tests only (*.spec.ts)
pnpm test:e2e             # run e2e tests only (*.e2e-spec.ts)
pnpm db:generate          # generate Drizzle migrations
pnpm db:migrate           # run migrations
pnpm db:studio            # open Drizzle Studio
```

Run a single test file:
```sh
cd apps/server && pnpm vitest run src/modules/friendships/application/use-cases/tests/send-friendship-request.spec.ts
```

### Web (`apps/web/`)
```sh
pnpm dev    # Vite dev server
pnpm build  # TypeScript + Vite build
pnpm lint   # ESLint
```

### Infrastructure
```sh
docker compose up -d   # start PostgreSQL (port 5432, user/pass: postgres, db: talkio)
```

The server requires a `.env` file. Tests use `.env.test`. The `pretest:e2e` script auto-runs migrations against the test database before e2e tests.

## Architecture — Server (`apps/server/`)

The backend follows **Clean Architecture** with **Domain-Driven Design**. Every feature lives under `src/modules/<module>/` and is split into three layers:

### Layer structure (per module)
```
domain/         # Entities, Value Objects, Domain Events — no external dependencies
application/    # Use Cases (return Either<Error, Value>), Repository interfaces, Event Subscribers
infra/          # Fastify controllers, Drizzle repositories, mappers, factories, module wiring
```

### Key architectural patterns

**Either monad** — all use cases return `Either<UseCaseError, Result>` (see `src/shared/domain/either.ts`). Never throw from use cases; return `left(error)` instead.

**AggregateRoot + Domain Events** — entities that emit events extend `AggregateRoot`. Events are added via `this.addDomainEvent(new SomeEvent(this))` and dispatched after persistence via `DomainEvents.dispatchEventsForAggregate(aggregate.id)`. The `InMemoryEventBus` (singleton initialized in `main.ts`) routes events to subscribers.

**AppModule contract** — each module exports a singleton implementing `AppModule` (`src/infra/contracts/app-module.ts`). Modules declare three optional hooks registered at startup:
- `registerDomainHandlers()` — subscribes domain event handlers
- `registerWsHandlers(app)` — registers WebSocket message handlers
- `routes(app)` — registers HTTP routes as a Fastify plugin

**Factory functions** — `infra/factories/drizzle/make-*.ts` files wire use cases with their real Drizzle repository implementations. Controllers call these factories to get configured use case instances.

**Mappers** — `infra/mappers/` convert between domain entities and Drizzle DB rows. Repositories use mappers; use cases never see raw DB types.

**WatchedList** — used inside aggregates (e.g., `MessagesWatchedList`) to track added/removed items for efficient persistence.

### Modules
- **identity** — User entity, BetterAuth integration (auth routes mounted as a Fastify plugin)
- **friendships** — `Friendship` aggregate with `pending → accepted/rejected` state machine; emits `FriendshipRequestSent/Accepted/Rejected` events
- **chat** — `Conversation` aggregate (direct or group), `Message` entity; emits `MessageReceived`, `GroupCreated`; direct messages sent over WebSocket
- **notifications** — listens to events from other modules and persists `Notification` entities

### Testing conventions
- **Unit tests** (`*.spec.ts`) use in-memory repositories from `test/repositories/` and entity factories from `test/factories/`
- **E2E tests** (`*.e2e-spec.ts`) hit a real test database via Supertest
- Path alias `@/` resolves to `src/`

## Architecture — Web (`apps/web/`)

- **TanStack Router** with file-based routing under `src/routes/`. Non-route files co-located in route folders are prefixed with `-` (e.g., `-chat.tsx`) to prevent them from being treated as routes.
- **TanStack Query** for server state (`src/lib/query-client.ts`)
- **Zustand** for client state
- **shadcn/ui** components in `src/components/ui/` (do not edit these directly; re-run `shadcn add` to update)
- **Tailwind CSS v4** — configured via Vite plugin, no `tailwind.config.js`
- Route tree (`src/routeTree.gen.ts`) is auto-generated by the TanStack Router Vite plugin — do not edit manually
